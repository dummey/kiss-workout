## Review: gitignore for multica workspace files

### Summary

The PR adds `.multica/` and `AGENTS.md` to `.gitignore` and removes them from git tracking. The `.multica/` part is correct. The `AGENTS.md` part is questionable and should be reverted.

---

### Findings

**1. `.multica/` — ✅ Correct**

The `.multica/` directory contains runtime files (`daemon_task_context.json`, `project/resources.json`) that are generated/managed by the multica daemon. These should not be committed. This aligns with the multica platform's own `.gitignore` (https://github.com/multica-ai/multica/blob/main/.gitignore) which includes `.multica/`.

**2. `AGENTS.md` — ❌ Should NOT be gitignored**

`AGENTS.md` is **not** in the multica platform's own `.gitignore`. It is tracked in this repo since the initial commit and contains project-specific agent identity configuration and workflow instructions. It is not a transient runtime artifact — it's project configuration that should be version-controlled.

The rationale in the PR comment ("agent runtime configuration injected into every turn") is incomplete: while the multica runtime does inject/update it, the file itself is meant to be tracked alongside the project. Adding it to `.gitignore` would cause it to be removed from tracking and lost on fresh clones.

**Recommendation:** Remove `AGENTS.md` from the gitignore additions. Keep it tracked.

**3. Additional files worth adding (prophylactic)**

Based on the multica platform's official `.gitignore`, the following directories are also generated by multica workflows and should be gitignored, even if they don't currently exist in this repo:

- `.context` — agent workspace context directory
- `.agent_context/` — agent context directory  
- `.claude/` — Claude-specific settings (user-specific, not project-specific)

These are absent from the current repo but adding them to `.gitignore` future-proofs against them being created by future multica runs.

---

### Suggested changes to the PR

1. **Keep** `.multica/` in `.gitignore` — correct
2. **Remove** `AGENTS.md` from `.gitignore` additions — it should remain tracked
3. **Add** `.context`, `.agent_context/`, `.claude/` to `.gitignore` for completeness

---

### Verification

- Current `.gitignore` has no multica-related entries
- `.multica/daemon_task_context.json` and `.multica/project/resources.json` are currently tracked in HEAD
- `AGENTS.md` is tracked in HEAD (since initial commit)
- The multica platform's own `.gitignore` (multica-ai/multica repo) confirms `.multica/` should be ignored, and does NOT ignore `AGENTS.md`
